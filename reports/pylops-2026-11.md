## Проблема й рішення

`NonStationaryConvolve1D.todense()` складав зсунуті імпульсні відгуки рядками, тоді як публічний forward operator використовує їх як стовпці. Щільна матриця представляла транспонований оператор: її множення та пряме обернення могли давати інший результат навіть для симетричних фільтрів, що змінюються вздовж сигналу.

Внесок транспонує зібрану матрицю та додає до наявного seeded тесту рівності для forward і adjoint. Matteo Ravasi перед merge переставив ці перевірки та зберіг матрицю в `Cdense`; виробниче виправлення залишилося тим самим. Його [коміт адаптації тесту](https://github.com/PyLops/pylops/commit/fe85bf75de06eb4900990d632db341f25dbe856e) є частиною прийнятого PR.

## Докази й межі

Опис PR документує попередню CPU-перевірку:

- На точній базі два selected cases падають, два controls проходять; після виправлення весь nonstationary module має 18 passes.
- Сусідні LinearOperator, convolution, smoothing і combination modules: 543 passes та три native skips; whole-tree Ruff проходить.
- Скалярний coordinate oracle: 128 дійсних float32/64 матриць. Окреме operator-action review: 48 cases для dense multiplication, adjoint та inversion; база проходить лише 12 діагональних controls.
- У побудованій задачі deconvolution з 51 відліком та condition number 1.65 щільне обернення мало відносну помилку 8.24% на базі й менше `2e-16` після зміни. Ітеративний operator control лишався нижче `1.5e-13`. Це конкретна тестова задача, не загальна оцінка виграшу.

Ці runtime-перевірки під час оновлення книги не повторювалися. Новий доказ тут — native GitHub merge, його час, commit і maintainer adaptation. Виправлення стосується одновимірного дійсного оператора; попередні multidimensional dense-shape та complex-filter обмеження не заявлені виправленими. Повна optional-dependency/GPU матриця, docs/gallery і package builds локально не перевірялися. Production-використання або дохід не встановлені.

## English summary

[PyLops #837](https://github.com/PyLops/pylops/pull/837) merged on 4 November 2026 at 21:34:47 UTC through Matteo Ravasi (`mrava87`), merge commit `06dc2761b4ffc1e6ae899f78a1a950d850a622c4`.

`NonStationaryConvolve1D.todense()` assembled shifted impulse responses as rows although the public forward operator uses columns. The resulting matrix represented the transpose, corrupting dense multiplication and direct inversion. The fix transposes the assembly and adds forward/adjoint equivalence assertions to the existing seeded test. Matteo rearranged those assertions before merging; his test-adaptation commit is linked above and the production correction is unchanged.

The PR records CPU validation: two selected baseline failures versus 18 passing nonstationary-module tests after the fix; 543 neighboring passes and three native skips; 128 coordinate-oracle matrices and 48 separate operator-action cases. A constructed 51-sample deconvolution improves dense-inverse relative error from 8.24% to below `2e-16`, with condition number 1.65. This is one explicit fixture, not a general performance claim.

Runtime tests were not rerun for this journal update. Native GitHub merge identity and the maintainer adaptation were freshly checked. The scope is one-dimensional real operators; existing multidimensional dense-shape and complex-filter limits remain. No local full optional-dependency/GPU matrix, production adoption or income claim.
